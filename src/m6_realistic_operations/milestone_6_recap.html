What you learned

Five last things an AI data engineer knows.

  1. Recalculate only what changed, and prove it equals everything.Each figure depends only on its own month's records. So a late September refund recalculates September. An incremental run is only worth having if a test shows it matches a full rebuild.
  2. A restatement must never be silent.The run before keeps the old figure and its own records. The comparison names the file that caused the change. The analyst repeats that reason. It does not work one out.
  3. A warning needs somewhere to go."Needs review" meant nothing until a person could decide it. A decision names a record, carries a name and a note, and the next run obeys.
  4. Test the judge, hold questions back, and measure the noise.A judge with a reference has a narrow job, and was tested on known cases first. Held-out questions catch a change that only fixes what its author could see. And the same analyst scores differently twice.
  5. The one who proposes a change must not judge it.The improver wrote the change. You approved it as reasonable. Code decided whether it worked, from scores the improver never saw. Both times, it rolled back, and that was the right answer.
