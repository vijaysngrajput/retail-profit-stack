What you learned

Five more things an AI data engineer knows.

  1. "No error" does not mean "loaded correctly".The naive loader never failed. It doubled a week of orders and emptied two columns, quietly. A loader must compare every file with what it expects before it loads anything.
  2. Make every step safe to repeat.A file is known by its content's fingerprint, and the database lets a fingerprint be loaded once. So a rerun, a retry, and a crash all end with the same records.
  3. AI suggests. A person approves. Code applies.The model read the values and worked out what cost_1 meant. But a swap of two amount columns passes every check code can make. So a person agrees to every mapping, once, and it is saved.
  4. A workflow that must wait needs its state on disk.A graph saves a checkpoint after every node and can pause for a person. After a restart, the file was still waiting, with the model's suggestion, and no model was called again.
  5. Running side by side buys time, and only time.The dispatcher has no AI in it, so you tested it with a stand-in first. Cost, quality, and the records were the same at one, five, or fifty at once. The slowest file set the clock.

Realistic operations

So far every file arrived once, complete, and on time. Real data does not. A refund turns up three weeks late. An order is corrected after it was counted. Next, the whole stack learns to cope.

  • Late and corrected records update only what they affect.
  • When a past figure changes, the run history shows it and the analyst explains it.
  • A rejected file that was never replaced becomes a warning in the answer.
